14. Configuração de rede e diagnóstico

Verificar conectividade por etapas, da interface até a aplicação.

Por que estudar este assunto?

Quando um sistema Web não abre, a causa pode ser cabo, IP, rota, DNS, porta, TLS ou aplicação. Testar etapas na ordem correta evita tentativas aleatórias.

O que você vai aprender

✓ Interpretar IP, prefixo, gateway e DNS
✓ Consultar rotas e interfaces
✓ Testar resolução de nomes e portas
✓ Organizar um diagnóstico por camadas

Conceitos fundamentais

Endereço IP

Identifica uma interface na rede.

Prefixo

Define a parte de rede.

Gateway

Roteador usado para outras redes.

DNS

Traduz nomes em endereços.

Porta

Identifica o serviço no equipamento.

Rota

Caminho escolhido para enviar pacotes.

Explicação passo a passo

Comece verificando se a interface está ativa e possui IP correto. Depois confirme a rota padrão.

Se o ping para um IP funciona, mas o nome não, o problema pode estar no DNS.

Se o host responde, mas a aplicação não, verifique porta, firewall e serviço.

Demonstração no terminal

  1. InterfaceVerifique estado e IP.
  2. RotaConfirme gateway padrão.
  3. IP externoTeste um endereço conhecido.
  4. DNSResolva um nome.
  5. PortaTeste a porta do serviço.
  6. AplicaçãoUse curl e analise o código HTTP.

Prática guiada

Resolva um cenário em que o servidor possui IP, mas o site não abre pelo nome. Registre cada teste e conclusão.

O que entregar

  • Objetivo da prática.

IA relacionada a esta aula

IA

Em uma aplicação Web com IA, o site pode funcionar enquanto o serviço de inferência está inacessível. Teste separadamente frontend, API, fila e servidor do modelo.

Revise antes de avançar

Questão: Se `ping 8.8.8.8` funciona, mas `ping exemplo.org` não, qual componente deve ser investigado primeiro?
