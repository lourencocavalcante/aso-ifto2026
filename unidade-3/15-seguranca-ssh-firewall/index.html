15. Segurança, SSH e firewall

Proteger o acesso remoto e limitar a exposição dos serviços.

Por que estudar este assunto?

Servidores conectados à rede recebem tentativas automáticas de acesso. Segurança começa reduzindo serviços, controlando contas e permitindo apenas conexões necessárias.

O que você vai aprender

✓ Compreender hardening e superfície de ataque
✓ Configurar autenticação SSH por chave
✓ Aplicar regras básicas de firewall
✓ Validar alterações sem perder o acesso

Conceitos fundamentais

Hardening

Conjunto de medidas para reduzir riscos.

Superfície de ataque

Pontos que podem ser explorados.

Chave SSH

Par de chaves usado para autenticação.

Firewall

Controla tráfego permitido e bloqueado.

Menor privilégio

Conceder apenas permissões necessárias.

Segredo

Senha, chave ou token que precisa ser protegido.

Explicação passo a passo

SSH por chave evita enviar senha e permite desabilitar autenticação fraca, mas a chave privada precisa ser protegida.

Antes de ativar firewall em acesso remoto, permita a porta SSH e mantenha outra sessão aberta para testar.

Não existe segurança apenas com uma ferramenta. Atualização, permissões, logs e backup trabalham em conjunto.

Comandos desta aula

ComandoPara que serve
ssh-keygen -t ed25519Cria um par de chaves.
ssh-copy-id usuario@servidorInstala a chave pública no servidor.

Demonstração no terminal

  1. Crie a chaveFaça isso no cliente.
  2. Copie a chaveUse `ssh-copy-id`.
  3. Teste outra sessãoConfirme login antes de alterar senhas.
  4. Valide SSHExecute `sshd -t`.
  5. Configure firewallPermita SSH e o serviço da aula.
  6. Verifique portasCompare `ss` com regras do firewall.

Prática guiada

Proteja uma VM com SSH por chave e firewall permitindo somente SSH e Web. Demonstre os testes de acesso permitido e bloqueado.

IA relacionada a esta aula

IA

Prompts, chaves de API e datasets são ativos de segurança. Nunca coloque segredos no código ou em páginas públicas. Considere também entradas maliciosas e uso excessivo do serviço.
