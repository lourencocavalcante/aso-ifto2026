Solução-base do projeto final

Servidor integrado para laboratório

Arquitetura de referência para Web, SFTP, compartilhamento, segurança, monitoramento e backup.

!

Não reproduza como entrega

Esta solução-base apresenta uma possibilidade de arquitetura. Cada equipe deve adaptar nomes, endereços, serviços, regras, evidências e justificativas. A reprodução integral será considerada ausência de autoria.

Arquitetura proposta

Windows hospedeiroVirtualBox
VM servidorUbuntu Server · 192.168.56.10
VM clienteWindows/Ubuntu · 192.168.56.20
  • Nginx para a página Web.
  • OpenSSH para administração e SFTP.
  • Samba ou NFS para arquivos.
  • UFW permitindo apenas serviços necessários.
  • Rsync ou tar para backup.

Etapa 1 — Preparar o VirtualBox

  1. Criar a VM servidor

    2 vCPUs, 2 a 4 GB RAM, 30 GB de disco, Adaptador 1 NAT e Adaptador 2 Rede Interna `LAB-ASO`.

  2. Criar a VM cliente

    Use Windows ou Ubuntu Desktop com a mesma rede interna.

  3. Definir IPs

    Servidor `192.168.56.10/24` e cliente `192.168.56.20/24`.

  4. Criar snapshot

    Registre o estado após instalação e atualização.

Etapa 2 — Configurar a base do servidor

Terminal
sudo apt update
sudo apt upgrade -y
sudo apt install nginx openssh-server samba ufw rsync -y
hostnamectl
ip -br a
systemctl --failed

Etapa 3 — Publicar o site

  1. Criar página

    Edite `/var/www/html/index.html` com apresentação da equipe e descrição do projeto.

  2. Validar

    Execute `sudo nginx -t`, `curl -I http://localhost` e acesse pelo cliente.

  3. Observar logs

    Use access.log e error.log durante os testes.

Etapa 4 — Arquivos e SFTP

  1. Criar grupo

    Use um grupo para a equipe do projeto.

  2. Configurar Samba ou NFS

    Crie um compartilhamento autenticado com permissões mínimas.

  3. Configurar SFTP

    Use conta restrita para recebimento de arquivos e teste pelo Windows Terminal.

Etapa 5 — Segurança

Terminal
sudo ufw default deny incoming
sudo ufw default allow outgoing
sudo ufw allow OpenSSH
sudo ufw allow 80/tcp
sudo ufw allow 445/tcp
sudo ufw enable
sudo ufw status verbose
sudo sshd -t
ss -tulpen

Se a equipe escolher NFS, substitua a regra de Samba por uma regra restrita à rede interna.

Etapa 6 — Backup e restauração

Terminal
sudo mkdir -p /backup/projeto
sudo rsync -aH /var/www/html/ /backup/projeto/web/
sudo rsync -aH /srv/samba/ /backup/projeto/arquivos/
sudo tar -czf /backup/projeto/configuracoes.tgz /etc/nginx /etc/ssh /etc/samba

Remova um arquivo de teste e restaure-o para demonstrar que o backup é utilizável.

Etapa 7 — Evidências obrigatórias

  • Diagrama com VMs, redes, IPs e serviços.
  • Inventário do servidor.
  • Capturas de funcionamento de cada serviço.
  • Saída do firewall e portas.
  • Logs de acesso e erros.
  • Teste de autenticação e permissão.
  • Backup e restauração.
  • Análise dos riscos e limitações.
