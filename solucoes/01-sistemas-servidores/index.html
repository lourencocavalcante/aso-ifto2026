Solução exemplo — Introdução aos sistemas de servidores

Identificar serviços de uma instituição e relacionar clientes, servidores, protocolos, portas e impacto de falhas.

!

Use apenas como referência

Esta solução não deve ser copiada, reproduzida integralmente ou entregue como trabalho próprio. Primeiro execute a prática sem consultar esta página. Depois, utilize o exemplo somente para comparar decisões, corrigir erros e compreender etapas que não ficaram claras.

O seu ambiente, comandos, evidências e explicações devem ser produzidos por você.

Ambiente no VirtualBox para Windows

  • VM 1: Ubuntu Server 24.04 LTS, 2 vCPUs, 2 GB RAM, 25 GB de disco.
  • VM 2: Ubuntu Desktop ou Windows 10/11, 2 vCPUs, 3 GB RAM.
  • Adaptador 1 das duas VMs: NAT.
  • Adaptador 2 das duas VMs: Rede Interna com o nome `LAB-ASO`.
Windows→VirtualBox→Servidor↔Cliente

Passo a passo detalhado

  1. Preparar o VirtualBox no Windows

    Instale o VirtualBox, abra o Gerenciador e confirme que a virtualização está habilitada. Crie as duas VMs e associe as imagens ISO.

  2. Configurar a rede do servidor

    Na VM servidor, abra Configurações → Rede. Mantenha o Adaptador 1 em NAT. Habilite o Adaptador 2 em Rede Interna e use o nome `LAB-ASO`.

  3. Configurar a rede do cliente

    Repita a mesma configuração na VM cliente. As duas VMs precisam usar exatamente o mesmo nome de rede interna.

  4. Identificar o servidor

    No servidor, execute `hostnamectl`, `ip -br a`, `free -h`, `df -h` e `ss -tulpen`. Registre hostname, IP, memória, disco e portas.

  5. Testar comunicação

    No cliente, use `ping IP_DO_SERVIDOR`. Depois teste uma porta conhecida com `nc -vz IP_DO_SERVIDOR 22`.

  6. Montar a tabela

    Registre pelo menos cinco serviços: Web, SSH, arquivos, impressão e DNS. Para cada um, informe cliente, servidor, protocolo, porta, usuários e impacto da falha.

Comandos de referência

Terminal
hostnamectl
ip -br a
free -h
df -h
ss -tulpen
ping -c 4 IP_DO_SERVIDOR
nc -vz IP_DO_SERVIDOR 22

Como validar

  • O cliente alcança o IP do servidor.
  • O SSH aparece em uma porta de escuta quando instalado.
  • A tabela relaciona corretamente serviço, protocolo e porta.
  • O impacto de falha está descrito em linguagem própria.

Erros comuns

  • As VMs usam nomes diferentes na Rede Interna.
  • O segundo adaptador não foi habilitado.
  • O aluno confundiu serviço com equipamento.
  • A porta foi copiada sem verificar no servidor.
