Solução exemplo — Virtualização e laboratório

Criar duas VMs comunicando-se em uma rede interna isolada.

!

Use apenas como referência

Esta solução não deve ser copiada, reproduzida integralmente ou entregue como trabalho próprio. Primeiro execute a prática sem consultar esta página. Depois, utilize o exemplo somente para comparar decisões, corrigir erros e compreender etapas que não ficaram claras.

O seu ambiente, comandos, evidências e explicações devem ser produzidos por você.

Ambiente no VirtualBox para Windows

  • VM Servidor: Ubuntu Server, 2 vCPUs, 2 GB RAM, 25 GB.
  • VM Cliente: Ubuntu Desktop, 2 vCPUs, 3 GB RAM, 30 GB.
  • Adaptador 1: NAT.
  • Adaptador 2: Rede Interna `LAB-ASO`.
Windows→VirtualBox→Servidor↔Cliente

Passo a passo detalhado

  1. Criar a VM servidor

    No VirtualBox, clique em Novo. Defina nome `srv-aso01`, selecione Linux/Ubuntu 64-bit, associe a ISO e configure CPU, memória e disco.

  2. Criar a VM cliente

    Repita para `cli-aso01`, usando Ubuntu Desktop ou Windows.

  3. Configurar adaptadores

    Com as VMs desligadas, abra Configurações → Rede. No Adaptador 1 selecione NAT. No Adaptador 2 marque Habilitar e selecione Rede Interna `LAB-ASO`.

  4. Instalar os sistemas

    Inicie cada VM e conclua a instalação. No servidor, instale o OpenSSH quando o instalador oferecer.

  5. Definir IPs da rede interna

    Use, por exemplo, `192.168.56.10/24` no servidor e `192.168.56.20/24` no cliente. Não configure gateway nessa interface interna.

  6. Testar a comunicação

    Execute ping nos dois sentidos. Em seguida, crie um snapshot chamado `Base limpa` em cada VM.

Comandos de referência

Terminal
ip -br a
ip route
ping -c 4 192.168.56.20
ping -c 4 192.168.56.10

Como validar

  • As VMs acessam a Internet pelo NAT.
  • As VMs comunicam-se pela rede interna.
  • O snapshot aparece no gerenciador do VirtualBox.
  • A rota padrão continua usando o adaptador NAT.

Erros comuns

  • Adicionar gateway também na rede interna.
  • Usar bridge em vez de rede interna.
  • Criar snapshot com a VM em estado inconsistente.
  • Dar pouca memória à VM Desktop.
