Solução exemplo — Samba

Criar compartilhamento autenticado e público somente leitura.

!

Use apenas como referência

Esta solução não deve ser copiada, reproduzida integralmente ou entregue como trabalho próprio. Primeiro execute a prática sem consultar esta página. Depois, utilize o exemplo somente para comparar decisões, corrigir erros e compreender etapas que não ficaram claras.

O seu ambiente, comandos, evidências e explicações devem ser produzidos por você.

Ambiente no VirtualBox para Windows

  • Ubuntu Server.
  • Cliente Windows 10/11.
  • Rede Interna `LAB-ASO`.
Windows→VirtualBox→Servidor↔Cliente

Passo a passo detalhado

  1. Instalar Samba

    Use apt.

  2. Criar grupo e usuário

    Crie `equipe` e associe um usuário.

  3. Criar diretórios

    Prepare `/srv/samba/equipe` e `/srv/samba/publico`.

  4. Aplicar permissões

    Defina grupo e modos adequados.

  5. Adicionar senha Samba

    Use `smbpasswd -a`.

  6. Configurar shares

    Adicione blocos ao final de `smb.conf`.

  7. Validar

    Use `testparm`.

  8. Reiniciar e testar

    No Windows, abra `\\IP_DO_SERVIDOR\equipe`.

Comandos de referência

Terminal
sudo apt install samba -y
sudo groupadd equipe
sudo useradd -m -G equipe aluno1
sudo smbpasswd -a aluno1
sudo mkdir -p /srv/samba/{equipe,publico}
sudo chown root:equipe /srv/samba/equipe
sudo chmod 2770 /srv/samba/equipe
sudo chmod 755 /srv/samba/publico
testparm
sudo systemctl restart smbd
smbclient -L //localhost -U aluno1

Como validar

  • O compartilhamento equipe exige login.
  • O usuário autorizado grava.
  • O compartilhamento público não permite escrita.
  • testparm não mostra erro.

Erros comuns

  • Usar 777.
  • Criar usuário apenas no Samba, não no Linux.
  • Não combinar permissões do filesystem.
  • Editar smb.conf sem backup.
